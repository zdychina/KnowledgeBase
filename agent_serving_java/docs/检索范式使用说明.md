# 检索范式（可插拔检索算子系统）使用说明

> 适用对象：用画布搭建/调试检索范式的人，以及通过接口调用范式做评测的测试系统。
> 入口：前端 kb-ui 左侧导航「**检索范式**」。
> 后端服务：`agent_serving_java`（`/api/v1/operator/*`、`/api/v1/paradigm/*`），与现有 `/api/v1/search` 并存、互不影响。

---

## 1. 这是什么

把检索流程拆成一个个**算子**（query_embed、dense_vector、fts、rrf、model_rerank、assemble…），在画布上**拖拽 + 连线 + 配参数**组成一张有向无环图（DAG），就是一个**范式**。范式可以：

- **试运行**：当场跑当前画布看效果；
- **发布**：固化成**不可变版本**，得到稳定的 `范式ID + 版本号`；
- **被测试系统调用**：`POST /api/v1/paradigm/{id}/search` 拿检索结果算指标（召回/精确/MRR/NDCG…）。

用途：测不同检索范式的增益（纯向量 vs 向量+重排 vs 多路融合…）、调参对比、为生产链产出喂给 LLM 的上下文。

---

## 2. 核心概念

| 概念 | 含义 |
|---|---|
| **算子 (Operator)** | 检索流程的最小可插拔单元，有类型化输入/输出端口（slot）和可调参数 |
| **slot** | 算子的输入/输出端口，有类型（向量/范围/候选/查询理解/上下文包…） |
| **范式 (Paradigm)** | 一张完整的检索 DAG（算子 + 连线 + 参数 + 终点） |
| **版本 (Version)** | 范式某次发布的**不可变快照**；同一 `ID+版本` 调用结果可复现 |
| **终点算子** | DAG 的出口：`collect`（候选列表，测试用）或 `assemble`（ContextPack，喂 LLM） |
| **检索范围 (textKind)** | dense_vector 的参数：在 raw_text / 生成问题 / 两者 中检索 |

## 3. 快速上手（1 分钟跑出结果）

1. 顶部/侧边确认**领域**为 `cloud_core_network`（当前库语料是 application-assurance 的 `aa-*` 命令，查询词用 `aa-interface` 这类才有结果）。
2. 「检索范式」→ **新建范式** → 填名称 → **模板**选 `① 纯向量检索（基线）` → **创建并编辑**。
3. 画布已自动连好 4 个算子。右侧「运行」框输入 `aa-interface` → **试运行草稿** → 下方出现候选列表 + 执行链路。
4. 想对比检索范围：点画布上的 **向量检索** 节点 → 右侧把「检索范围」改成 `question` → 再试运行（候选会整批变化）。
5. 满意后：**校验** → **发布**（得到 v1）。右侧「接口调用」区出现端点和「复制 curl」。

---

## 4. 画布操作

- **加算子**：从左侧面板把算子**拖**到画布。
- **连线**：从一个节点**右侧输出口**拖到下游**左侧输入口**。
- **选中**：点节点 → 蓝色高亮环，右侧显示「节点参数」。
- **配参数**：右侧面板按算子 schema 自动渲染（下拉/数字/开关/标签/权重）。
- **设输出终点**：右侧「输出（终点算子）」下拉，选 `collect → candidates` 或 `assemble → contextPack`（被选节点显示绿色环）。
- **删除节点/连线**：选中后按 `Delete`；节点也可在右侧「删除节点」。
- **连线帮助**：画布右上角「？连线帮助」查看规则。

---

## 5. 连线规则

1. **方向**：右侧输出口 → 下游左侧输入口（输出↔输出、输入↔输入连不了）。
2. **类型一致**：同类型才能连（向量→向量、范围→范围、候选→候选…）。唯一例外：**候选 → 融合算子的多入口**。类型不符**连不上**并弹中文提示。
3. **单入 / 多入**：普通输入口只接一条（再连会替换旧线）；融合算子的 `candidates` 可接多条。
4. **不能成环**：整图必须是 DAG。
5. **入口**：`query` 输入口可**不连**（运行时自动用请求的查询）；**检索算子的 `scope` 必须连 `scope_resolve`**，否则校验报 `missing_required_input`。
6. **终点**：必须选一个终点节点的输出 slot 作为范式结果。

## 6. 算子目录（共 18 个）

| 类别 | 算子 | 输入 → 输出 | 关键参数 |
|---|---|---|---|
| **入口** | `request_input` | (无) → query(文本) | — |
| **查询变换** | `query_embed` | query → queryEmbedding(向量) | — |
| | `hyde` | query → queryEmbedding(向量) | — (先用 LLM 生成假设文档再嵌入) |
| | `query_understanding` | query → understanding(查询理解) | useLlm(建议性) |
| | `multi_query` | query → variants(字符串列表) | maxVariants ⚠️暂无下游消费者 |
| **范围** | `scope_resolve` | (无) → scope(范围) | — |
| **检索** | `dense_vector` | queryEmbedding, scope → candidates | **textKind**(raw_text/question/both), topK |
| | `fts` | query, scope → candidates | topK（三级降级 tsvector→trigram→LIKE） |
| | `entity_exact` | understanding, scope → candidates | topK（实体名精确匹配） |
| | `graph_expand` | seeds(候选), scope → candidates | maxDepth, maxResults, relationTypes |
| **融合** | `rrf` | candidates(多入) → candidates | k |
| | `weighted_rrf` | candidates(多入) → candidates | k, weights(**按 source 名**) |
| | `identity` | candidates → candidates | — (直通) |
| **重排** | `model_rerank` | candidates, query → candidates | topK, threshold（跨编码器模型） |
| | `llm_rerank` | candidates, query → candidates | topK（LLM 列表式） |
| | `score_rerank` | candidates → candidates | threshold（按分数兜底） |
| **输出** | `collect` | candidates → candidates(终点) | maxItems |
| | `assemble` | candidates, understanding, scope → contextPack(终点) | maxItems, maxExpanded, relationExpansion |

说明：
- **向量化可替换**：用 `query_embed` 的地方都能换成 `hyde`（输出都是 queryEmbedding）。
- **weighted_rrf 的 weights 按 source 名**（如 `dense_vector`、`lexical_bm25`）键控，不是按节点 id。
- **graph_expand** 产出的是段落级候选（适合补充上下文/collect），与 unit 级候选混融需注意语义。

## 7. 一键模板（共 11 个）

新建范式时在「模板」下拉选择，自动生成连好线的画布：

| 模板 | 链路 | 用途 |
|---|---|---|
| 空白画布 | — | 从零拖拽 |
| ① 纯向量检索 | query_embed → dense_vector → collect | 测向量召回，对比 textKind |
| ② 向量 + 模型重排 | … → dense_vector → model_rerank → collect | 测重排增益 |
| ③ 多路混合 + 加权融合 | dense ‖ fts → weighted_rrf → collect | 复刻多路融合 |
| ④ 生产链 | 理解+向量+实体 → 融合 → 重排 → assemble | 产 ContextPack 喂 LLM |
| ⑤ HyDE 向量检索 | hyde → dense_vector → collect | 测 HyDE 增益 |
| ⑥ 纯全文检索 | fts → collect | 纯词法，不用向量 |
| ⑦ 纯实体精确 | query_understanding → entity_exact → collect | 命令/网元名精确查找 |
| ⑧ 向量 + 图扩展 | dense_vector → graph_expand → collect | 召回 + 关系图邻居扩展 |
| ⑨ 向量 + LLM 重排 | … → llm_rerank → collect | LLM 列表式重排 |
| ⑩ 显式入口节点 | request_input → query_embed → … | 用 Input 节点显式接查询 |
| ⑪ 三路全融合 + 生产链 | dense ‖ fts ‖ entity → rrf → model_rerank → assemble | 三路召回完整生产链 |

## 8. 生命周期

```
[新建] → 草稿(可任意编辑/试运行)
   │
   ├─[校验]  编译检查（连线/类型/环/必填/参数）→ 不通过会列出具体节点/边
   │
   ├─[发布]  先校验通过 → 生成不可变版本 vN，状态变「已发布」
   │           └─ 版本内容不可变；可多次发布得到 v1/v2/v3…
   │
   ├─[回滚]  把「当前版本」指回某历史版本（版本本身不变）
   │
   ├─[归档]  状态→已归档（软隐藏，数据仍在，可在「已归档」页签看）
   │
   └─[删除]  仅对**已归档**的范式可删（两步防误删）；级联删除所有版本，不可恢复
```

- **草稿/已发布/已归档** 三个状态，列表按状态分页签。
- **发布版本号** = 历史最大版本 + 1（回滚后再发布也不会撞号）。

## 9. 运行：试运行 vs 运行已发布

右侧「运行」区：

- **试运行草稿（不落库）**：跑**当前画布**（含未保存改动），调 `POST /api/v1/paradigm/run`。用于编辑时快速看效果。
- **运行已发布**：选版本号（当前版本 / v1 / v2…），跑那个**不可变版本**，调 `POST /api/v1/paradigm/{id}/search?version=N`。这就是测试系统的调用方式。

结果面板展示：候选列表（id/source/score/text）或 ContextPack，以及每个算子的执行链路耗时。

## 10. 测试系统调用（接口）

范式发布后，编辑器右侧「接口调用」区可看到端点，并能**一键复制 curl**。

**调用已发布版本：**
```
POST /api/v1/paradigm/{paradigmId}/search?version={N}
Content-Type: application/json

{ "query": "aa-interface", "domain": "cloud_core_network", "channel": "prod", "debug": false }
```
- `version` 省略 = 用当前发布版本（latest）；指定 = 锁定该不可变版本（结果可复现）。
- `domain` 省略 = 默认领域；`channel` 省略 = 领域默认渠道。

**响应（取决于终点算子）：**
- 终点是 `collect` → `{ "candidates": [ { "id", "score", "source", "scoreChain", "metadata" }, ... ] }`
- 终点是 `assemble` → `{ "contextPack": { ...与 /api/v1/search 同结构... } }`
- `debug:true` 时附 `trace`（各算子耗时）。

**完整 curl 示例**（经 main_control 反代，与前端同源可直接跑；测试系统若直连 serving 把域名换成 serving 的 host:8081，路径不变）：
```bash
curl -X POST 'http://<host>/api/control-plane/api/v1/proxy/cloud_core_network/serving/api/v1/paradigm/pd-xxxxxxxx/search?version=1' \
  -H 'Content-Type: application/json' \
  -d '{"query":"aa-interface","domain":"cloud_core_network"}'
```

**其它接口：**
| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/v1/operator/catalog` | 算子目录（前端画布据此渲染） |
| POST | `/api/v1/paradigm` | 新建草稿 `{name,description?,graph?}` |
| GET | `/api/v1/paradigm` · `/{id}` | 列表 / 详情 |
| PUT | `/api/v1/paradigm/{id}` | 改草稿 `{graph}` |
| POST | `/api/v1/paradigm/{id}/publish` | 发布（先编译校验） |
| POST | `/api/v1/paradigm/{id}/rollback?version=N` | 回滚当前版本 |
| POST | `/api/v1/paradigm/{id}/archive` | 归档 |
| DELETE | `/api/v1/paradigm/{id}` | 删除（仅已归档） |
| GET | `/api/v1/paradigm/{id}/versions` · `/versions/{v}` | 版本列表 / 某版本 |
| POST | `/api/v1/paradigm/{id}/validate` · `/dryrun` | 校验草稿 / 试运行草稿 |
| POST | `/api/v1/paradigm/run` · `/validate` | 内联（不落库）执行 / 校验 |

## 11. 检索范围（textKind）说明

`dense_vector` 的「检索范围」参数控制在哪种检索单元上做向量检索：

| 取值 | 实际过滤（asset_retrieval_units.unit_type） |
|---|---|
| `raw_text` | 原文单元 |
| `question` | 生成问题单元（generated_question） |
| `both` | 两者都查（合并） |

> 注：嵌入表 `asset_retrieval_embeddings.text_kind` 当前实测全是 `full`，raw_text vs question 的区分实际在 `asset_retrieval_units.unit_type`，已据此实现。

## 12. 常见问题 / 排错

- **画布没"模板"/没新功能** → 浏览器硬刷新（Ctrl+Shift+R）。
- **连线连不上** → 类型不符（看弹出的中文提示）；确认是右输出口→左输入口。
- **校验报 `missing_required_input`** → 某必填输入没连；检索算子的 `scope` 必须连 `scope_resolve`。
- **运行/发布报参数错误** → 数字框别留空（清空会回落默认值）；权重 key 别留空。
- **运行没结果但无报错** → 查询词不在语料里（换 `aa-interface`/`custom-record`/`application assurance`）；或 dense_vector 选了某 textKind 而该类无数据。
- **运行转圈较久** → 首次向量化要调嵌入服务（约 2 秒正常）。
- **删除按钮没有** → 只有「已归档」的范式才有删除（先归档）。
- **回滚后想再发布** → 直接发布即可，版本号自动取最大+1，不会撞号。

## 13. 与现有检索的关系

- 本系统是**新增子系统**，与现有 `/api/v1/search` 固定流水线**并存**，现有 pipeline 文件零改动。
- 范式存储在控制库（`operator_paradigm` / `operator_paradigm_version`），与领域知识库分开。
- 设计文档见 `docs/requirements/2026-06-22-pluggable-retrieval-operator-system-prd.md`（PRD）与 `...-plan.md`（实施计划）。
